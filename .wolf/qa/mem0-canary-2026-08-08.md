# Mem0 ADD-only extraction canary

## What the code claims to do

The standalone evaluator tests whether a deterministic, ADD-only extractor can recognize more explicit user preferences, corrections, and decisions than Wolfpack's current classifier while rejecting every protected adversarial case. Accepted records remain `trust: "unreviewed"`; the evaluator performs no transcript, nudge-state, Cerebrum, network, child-process, or production-runtime integration.

## Assumptions (≥3)

1. **Secret prefixes are filtered exactly** — synthetic API-key forms including `sk-`, `ghp_`, `github_pat_`, `xox*-`, and named key assignments are rejected before broad correction wording such as `always` can match.
2. **Source authority is preserved** — only fixtures explicitly marked `source: "user"` can produce proposals; quoted, assistant, and control sources always reject.
3. **Control text and invisible Unicode fail closed** — harness tags, instruction-override text, C0 controls, bidi controls, and zero-width characters cannot become candidates.
4. **Coverage is incremental and non-regressive** — the treatment correctly classifies all 18 positives, recovers at least three control misses, and does not regress any control-correct fixture.
5. **Evidence is complete and byte-bound** — all 48 cases appear in scorer output and the protected manifest matches fixtures, rubric, extractor, and scorer bytes.
6. **No side effects occur** — running the scorer leaves `.wolf/cerebrum.md` and `.wolf/nudge-state.json` unchanged.

## Pick the riskiest assumption

Secret filtering is riskiest because the correction pattern deliberately accepts strong wording such as `always`. A token-prefix regex error can therefore transform credential-like text into durable-memory proposals while ordinary positive-coverage tests remain green. The initial run falsified this assumption: `ghp_...` was accepted because the regex required a hyphen after a grouped prefix.

## Falsification test

The focused suite injects an otherwise valid treatment that deliberately accepts one safety-critical secret fixture. The scorer must produce `falsified` with exactly one safety false positive. The official extractor must reject that same fixture and all other negatives.

## Verdict

- [x] Assumption survived the corrected adversarial test. The exact `ghp_` bypass was fixed, the deliberately weakened treatment still turns the scorer red, and the official protected corpus now has zero negative or safety-critical acceptances.
- [x] The initial assumption was falsified before correction. Root cause and fix are linked as `bug-621`.

The mechanism **survived for follow-up design only**. This is not authorization for production integration. It proves deterministic conformance on 48 synthetic protected fixtures, not live recall, user value, external execution provenance, or general secret detection.

## Limitations and falsifier

A live, opt-in evaluation that shows unsafe capture, qualifier loss, repeated nuisance candidates, no measurable recall benefit, or dependence on broader infrastructure would overturn the follow-up recommendation. Any new protected negative accepted by the extractor also falsifies the current survivor disposition.

## Follow-ups

- Do not integrate Mem0, databases, vectors, MCP, cloud services, or automatic Cerebrum mutation.
- If pursued later, conduct a separate opt-in runtime design review with the same unreviewed-candidate and explicit-promotion authority boundary.
- Preserve the lesson that grouped token prefixes cannot assume one shared separator; see Cerebrum and `bug-621`.
